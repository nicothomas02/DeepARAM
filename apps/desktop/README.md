# DeepARAM desktop app (Windows and Linux)

A small Tauri 2 app that opens deeparam.com in its own window. All features (Tier List, Simulator, PBE, champion pages) come straight from the live site, so the app never needs an update for new content. The same Rust code builds for Windows and Linux. Platform-only bits sit behind `cfg(target_os)` and platform-only bundle settings in `src-tauri/tauri.<platform>.conf.json`.

What the app adds on top of the site:

- Native window that remembers its size and position, and reopens on the page you used last.
- Tray icon: Tier List, Simulator, Patches and PBE shortcuts, "Check for patch updates", toggles for patch notifications and "Start with Windows" / "Start at login" (starts hidden in the tray; not offered in the Flatpak, whose sandbox can't add login items).
- Closing the window keeps the app in the tray; Quit is in the tray menu. A second launch focuses the running app. On a Linux desktop with no tray (stock GNOME without the AppIndicator extension) closing quits instead, so the app never runs with no way back to it.
- Shortcuts: Ctrl+1 to Ctrl+7 for Home, Tier List, Simulator, Patches, PBE, Champions and The Kitchen; Ctrl+Shift+C copies the page's link. Back (Alt+Left), reload (F5) and zoom (Ctrl +, Ctrl −, Ctrl 0) come with the web view.
- Patch notifications: every 30 minutes it reads `https://deeparam.com/data/app-status.json` (`web/src/app/data/app-status.json/route.ts`, also read by the Mac, iPhone and iPad apps) and notifies when the live patch or the PBE build changes.
- Offline: a bundled start page (`ui/index.html`) waits for the connection and retries; while browsing, a banner shows when the connection drops. WebView2 (Windows) and WebKitGTK (Linux) keep their own disk cache, so pages already opened load fast.
- Links to other sites open in the default browser.
- Nothing is drawn over the game (Nico 2026-11-21). The old see-through panel over League (`overlay.rs`, `ui/overlay.html`, Ctrl+Shift+O) is gone; everything for a Mayhem game shows in the companion window below, which goes full screen on a monitor League isn't on. That also keeps frames: no always-on-top window for Windows to blend over the game, no global hotkey hook, and fewer requests to the game.
- In-game watcher (`src-tauri/src/ingame.rs`): during an ARAM Mayhem game it reads League's Live Client Data API on `127.0.0.1:2999` (`/gamestats` and `/playerlist` every 2 seconds, `/eventdata` every 15 seconds of game time for the review). Outside games it costs one refused local connection every 5 seconds.
- Augment offers off the screen (`src-tauri/src/augscan.rs`, Windows only): Live Client Data doesn't report augments, so in the game's first 90 seconds and for 60 seconds after reaching level 7, 11 or 15 (longer while an offer stays up), it copies the middle of League's window once a second, the way a screenshot does, and reads the card titles with Windows' built-in text recognition (Windows.Media.Ocr, English names from `/data/augment-picks.json`, a few misread letters allowed on long names). Once the offer is gone for two reads it stops until the next augment level. The picture is never saved or sent. Borderless or Windowed only: an exclusive Fullscreen game copies as black and is skipped. The tray's "Mayhem companion > Read augment offers off the screen" turns it off. Riot's rules: it reads only what's already on your screen, never game memory; the companion highlights the offered augments best first and you pick (apps may highlight decisions, not make them), with no win rates.
- Companion window (`src-tauri/src/companion.rs`, `ui/companion.html`): a normal window that opens by itself when a Mayhem champion select starts. Once the game is on it goes full screen on a monitor League isn't on (found from League's window, else the non-main monitor), with three columns (quick build and items, augments, the owner's live chance); Esc leaves full screen and F11 goes back. With one monitor it stays an ordinary window. It goes to the second monitor as soon as it opens in champion select. It looks like the site: the champion's splash as a banner, Mona Sans (bundled in `ui/fonts`), rarity rings on augments, the Howling Abyss art (`ui/art`) on the start screen. When an offer leaves the screen without a tap (picked in the game), its augments stay up as "Which one did you take?" for a one-tap mark. After the game, Victory or Defeat comes from the client's end-of-game screen (`/lol-end-of-game/v1/eog-stats-block`) when the game's feed closed before reporting it. On the app's first launch on a PC it turns on start-at-login (hidden in the tray), so games are followed without opening it; the tray turns that off. The site-owner check retries every 5 minutes when it gets no answer, not every poll.
  Testing: debug builds take `DEEPARAM_LCU=port:password` (a fake League client) and `DEEPARAM_FAKE_SCREEN=<file>` (a JSON list of `[text, x]` card titles standing in for the screen), so a whole scripted game can run on Linux against fake servers on 127.0.0.1:2998/2999. While an augment offer is read off the screen, the offered augments show at the top, best first, and tapping the one you take re-ranks the rest. It ranks your own champion and your bench by strength (`https://deeparam.com/data/team-fit.json`, the same scoring as the site's Tier List > Champions > Best pick). It suggests and never picks, and it shows no player names. After each game (5 minutes or longer) it shows the game review (`src-tauri/src/review.rs`): the predicted chance to win over the game, its turning points and from when a surrender would have paid off, labelled as predicted. During a game it shows, for everyone, your champion's augments best first (`https://deeparam.com/data/augment-picks.json`, best first, each with its DeepScore on the champion, never raw win rates): tap the one you took, or type a few letters and press Enter in the companion, and the rest re-rank by synergy with it, with a search box for augments outside the top 8, and "Augment pick" lights up when you reach 1, 7, 11 or 15. Above that it names your next two items from the champion's build, skipping what you own, highlighted while you're dead. When the enemy team's damage leans 65% or more one way (their champions' usual mix, updated by the finished items they buy, `https://deeparam.com/data/damage-types.json`), it says so in one line, which League doesn't show. It doesn't prescribe a defense item: none has been shown to pay off yet. In game the item box shows at most two tips, most useful first: where your next skill point goes (R at 6, 11 and 16; with Back to Basics only when the R has a passive, like Ryze or Pantheon), what your gold buys now toward the next item (official item recipes), the stat-cap guard (near Mayhem's 5.0 attack speed cap, attack-speed items move back; crit past 100% turns into attack damage in Mayhem, so crit isn't guarded; past 100 haste it notes that each point cuts cooldowns less), penetration when two or more enemies stack your damage's resist (or flat pen when they build none), a sell suggestion once all six slots are full, and the enemy damage split. Its build switches to your champion's matching build style once your augments point to one, and stacking items (Hubris, Heartsteel, tear items) go first. In champion select it adds a one-glance plan for your champion (skill order, first three items) and, once all five are in, one line if your team has no frontline or almost no magic or physical damage. The in-game watcher samples the game for the review every 15 seconds of game time. Only the site owner's Riot account (checked with the site's `/api/history`, like the My Stats helper) also gets the live chance and surrender line during the game. Riot's rules don't let apps draw conclusions for players mid-game, so nobody else gets that. It reads the League client's local API (lockfile on 127.0.0.1) every 3 seconds while the client is open, and all of the game's data every 5 seconds in game. While the client is closed it only checks the lockfile and the list of running programs every 15 seconds; PowerShell (to find a client installed elsewhere) runs only once the client is actually running. The tray's "Mayhem companion" menu turns it off ("Open by itself"), turns off reading the screen, or keeps it out of full screen, and closing it keeps it shut until the next champion select.

## Build

On Windows or Linux with Node 22 and Rust stable. Linux also needs the WebKitGTK and tray libraries
(Debian/Ubuntu: `sudo apt install libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev patchelf`):

```
cd apps/desktop
npm ci
npm run dev      # run against the live site
npm run build    # Windows: bundle/{nsis,msi}; Linux: bundle/{appimage,deb,rpm} under src-tauri/target/release
```

CI (`.github/workflows/desktop-app.yml`) lints, tests and builds the Windows installers and the Linux AppImage, .deb, .rpm and Flatpak on every change under `apps/desktop/`, and keeps them as a workflow artifact for 14 days. Public downloads come only from `release.yml` (a `v*` tag or "Run workflow"), which attaches them to a GitHub release next to the Mac app. Bump `version` in `src-tauri/tauri.conf.json` (and `Cargo.toml`, `package.json`) for a new release. Ask Nico before putting it in the Microsoft Store, Flathub, the Snap Store or any other store.

The installers aren't code-signed yet, so Windows SmartScreen shows "Windows protected your PC" on first run (More info, then Run anyway).

Icons are generated from `app-icon.png` with `npm run icons`.

## Linux packages

- **AppImage**: one file that runs on most distributions (`chmod +x`, then open it). Built on Ubuntu 22.04 so it works on glibc 2.35 and newer.
- **.deb** (Debian, Ubuntu, Mint) and **.rpm** (Fedora, openSUSE): install with the system's package tool; they pull in WebKitGTK and the tray library.
- **Flatpak** (`flatpak/`): app id `com.deeparam.DeepARAM` on the GNOME runtime. It repackages the .deb, so CI builds a `.flatpak` bundle you install with `flatpak install --user DeepARAM.flatpak`. Steps to build it yourself are at the top of `flatpak/com.deeparam.DeepARAM.yml`. Putting it on Flathub would need a build from source with vendored crates and Nico's go-ahead.

The Linux builds are x86_64 only for now.
