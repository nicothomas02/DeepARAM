# DeepARAM desktop app (Windows and Linux)

A small Tauri 2 app that opens deeparam.com in its own window. All features (Tier List, Simulator, PBE, champion pages) come straight from the live site, so the app never needs an update for new content. The same Rust code builds for Windows and Linux. Platform-only bits sit behind `cfg(target_os)` and platform-only bundle settings in `src-tauri/tauri.<platform>.conf.json`.

What the app adds on top of the site:

- Native window that remembers its size and position, and reopens on the page you used last.
- Tray icon: Tier List, Simulator, Patches and PBE shortcuts, "Check for patch updates", toggles for patch notifications and "Start with Windows" / "Start at login" (starts hidden in the tray; not offered in the Flatpak, whose sandbox can't add login items).
- Closing the window keeps the app in the tray; Quit is in the tray menu. A second launch focuses the running app. On a Linux desktop with no tray (stock GNOME without the AppIndicator extension) closing quits instead, so the app never runs with no way back to it.
- Shortcuts: Ctrl+1 to Ctrl+7 for Home, Tier List, Simulator, Patches, PBE, Champions and The Kitchen; Ctrl+Shift+C copies the page's link. Back (Alt+Left), reload (F5) and zoom (Ctrl +, Ctrl −, Ctrl 0) come with the web view.
- Patch notifications: every 30 minutes it reads `https://deeparam.com/data/app-status.json` (`web/src/app/data/app-status.json/route.ts`, also read by the Mac, iPhone and iPad apps) and notifies when the live patch or the PBE build changes.
- Offline: a bundled start page (`ui/index.html`) waits for the connection and retries; while browsing, a banner shows when the connection drops. WebView2 (Windows) and WebKitGTK (Linux) keep their own disk cache, so pages already opened load fast.
- Links to other sites open in the default browser.
- In-game overlay (`src-tauri/src/overlay.rs`, `ui/overlay.html`): during an ARAM Mayhem game, a small see-through panel at the left or right edge of the screen shows the champion page's quick build for the champion you're on: skill order, spells, items and the top 3 prismatic, gold and silver augments. It reads only League's Live Client Data API on `127.0.0.1:2999` (the game mode, your Riot ID and the player list, every 5 seconds) and the builds from `https://deeparam.com/data/overlay.json` (`web/src/app/data/overlay.json/route.ts`). No game memory, no injection: it's an ordinary always-on-top window that clicks pass through, so it shows over League in Borderless or Windowed mode but not exclusive Fullscreen. Ctrl+Shift+O hides or shows it (held only during a game; in "only when useful" mode the choice lasts until the panel would next appear or go by itself); the tray's "In-game overlay" menu turns it off, moves it to the other side, or switches between "only when useful" (the default: the first 90 seconds, while you're dead, and 30 seconds after reaching an augment level, 1, 7, 11 and 15) and all game. That mode reads `/playerlist` every 2 seconds during a game.
  Riot's rules it keeps to: only static picks available before the game, never augment win rates (banned in overlays), nothing about other players, no timers, and it never picks for you. The panel's web view is only created when a Mayhem game starts and destroyed when it ends, so outside games the overlay costs one refused local connection every 5 seconds. Debug builds read the builds from `DEEPARAM_OVERLAY_DATA` instead, for testing against a fake game on port 2999.
- Companion window (`src-tauri/src/companion.rs`, `ui/companion.html`): a normal window, meant for a second screen, that opens by itself when a Mayhem champion select starts. It ranks your own champion and your bench by strength (`https://deeparam.com/data/team-fit.json`, the same scoring as the site's Tier List > Champions > Best pick). It suggests and never picks, and it shows no player names. After each game (5 minutes or longer) it shows the game review (`src-tauri/src/review.rs`): the predicted chance to win over the game, its turning points and from when a surrender would have paid off, labelled as predicted. During a game it shows, for everyone, your champion's augments best first (`https://deeparam.com/data/augment-picks.json`, a ranking only, never win rates): click the one you took on the in-game overlay (during a pick it takes clicks without taking focus from the game), or type a few letters and press Enter in the companion, and the rest re-rank by synergy with it, with a search box for augments outside the top 8, and "Augment pick" lights up when you reach 1, 7, 11 or 15. Above that it names your next two items from the champion's build, skipping what you own, highlighted while you're dead. When the enemy team's damage leans 65% or more one way (their champions' usual mix, updated by the finished items they buy, `https://deeparam.com/data/damage-types.json`), it says so in one line, which League doesn't show. It doesn't prescribe a defense item: none has been shown to pay off yet. In game the item box shows at most two tips, most useful first: where your next skill point goes (R at 6, 11 and 16, with Back to Basics too, since its R passive still works), what your gold buys now toward the next item (official item recipes), the stat-cap guard (near Mayhem's 5.0 attack speed cap, attack-speed items move back; crit past 100% turns into attack damage in Mayhem, so crit isn't guarded; past 100 haste it notes that each point cuts cooldowns less), penetration when two or more enemies stack your damage's resist (or flat pen when they build none), a sell suggestion once all six slots are full, and the enemy damage split. Its build switches to your champion's matching build style once your augments point to one, and stacking items (Hubris, Heartsteel, tear items) go first. In champion select it adds a one-glance plan for your champion (skill order, first three items) and, once all five are in, one line if your team has no frontline or almost no magic or physical damage. The overlay samples the game for the review every 15 seconds of game time, so the review needs the overlay switched on. Only the site owner's Riot account (checked with the site's `/api/history`, like the My Stats helper) also gets the live chance and surrender line during the game. Riot's rules don't let apps draw conclusions for players mid-game, so nobody else gets that. It reads the League client's local API (lockfile on 127.0.0.1) every 3 seconds while the client is open, and nothing while it's closed. The tray's "Companion window in champ select and after games" turns it off, and closing it keeps it shut until the next champion select.

## Build

On Windows or Linux with Node 22 and Rust stable. Linux also needs the WebKitGTK and tray libraries
(Debian/Ubuntu: `sudo apt install libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev patchelf`):

```
cd apps/desktop
npm ci
npm run dev      # run against the live site
npm run build    # Windows: bundle/{nsis,msi}; Linux: bundle/{appimage,deb,rpm} under src-tauri/target/release
```

CI (`.github/workflows/desktop-app.yml`) lints, tests and builds the Windows installers and the Linux AppImage, .deb, .rpm and Flatpak on every change under `apps/desktop/`, and keeps them as a workflow artifact for 14 days. Public downloads come only from `release.yml` (a `v*` tag or "Run workflow"), which attaches them to a GitHub release next to the Mac app. Bump `version` in `src-tauri/tauri.conf.json` (and `Cargo.toml`, `package.json`) for a new release. Ask Nico before putting it in the Microsoft Store, Flathub, the Snap Store or any other store.

The installers aren't code-signed yet, so Windows SmartScreen shows "Windows protected your PC" on first run (More info, then Run anyway).

Icons are generated from `app-icon.png` with `npm run icons`.

## Linux packages

- **AppImage**: one file that runs on most distributions (`chmod +x`, then open it). Built on Ubuntu 22.04 so it works on glibc 2.35 and newer.
- **.deb** (Debian, Ubuntu, Mint) and **.rpm** (Fedora, openSUSE): install with the system's package tool; they pull in WebKitGTK and the tray library.
- **Flatpak** (`flatpak/`): app id `com.deeparam.DeepARAM` on the GNOME runtime. It repackages the .deb, so CI builds a `.flatpak` bundle you install with `flatpak install --user DeepARAM.flatpak`. Steps to build it yourself are at the top of `flatpak/com.deeparam.DeepARAM.yml`. Putting it on Flathub would need a build from source with vendored crates and Nico's go-ahead.

The Linux builds are x86_64 only for now.
